# Modern Image Optimization: WebP, AVIF, CLS Prevention, and Mobile Caching

Unoptimized images are the #1 cause of bloated page weights and poor Core Web Vitals. Worse, when images load asynchronously without reserved dimensions, the surrounding text and buttons jump down the screen—causing **Cumulative Layout Shift (CLS)** right as the user tries to click a button.

Whether you are building an Astro landing page, a Vite dashboard, or a React Native mobile app, following these image engineering rules keeps every screen instant and rock-steady.

---

## 1. Choosing the Right Raster Format

Never ship raw `.png` or `.jpg` exports for photographic content.

| Format | Best Used For | Compression Savings | Browser / OS Support |
| :--- | :--- | :--- | :--- |
| **`.avif`** | Hero banners, marketing photography, product shots | **~50% smaller** than JPEG at equal visual quality. | All modern browsers, iOS 16+, Android 12+. |
| **`.webp`** | General UI images, user avatars, blog thumbnails, fallbacks | **~30% smaller** than JPEG; supports transparency like PNG! | Universal across Web, iOS, and Android. |
| **`.png`** | **Strict Exceptions Only:** App Store icons, Apple Touch Icons, OpenGraph cards (when required by scrapers) | Lossless, very heavy for photos. | Universal. |

> **Rule of Thumb:** If an image needs a transparent background (like a product cutout or 3D floating graphic), export it as a **transparent `.webp`** instead of a `.png` to slash its file size by 60%–75%.

---

## 2. Eliminating Layout Shift (CLS) on the Web

When a browser parses `<img src="banner.webp" />` without dimensions, it initially renders the image at `0×0` pixels. Half a second later, when the image finishes downloading, the browser suddenly expands the box to `800×450`, pushing all page content downward.

### Always Reserve Space with `width`/`height` or `aspect-*`
Always provide explicit `width` and `height` attributes (so the browser calculates the aspect ratio before the network request even starts) or enforce a Tailwind `aspect-*` container:

```tsx
// ❌ Bad: Causes layout jump when image loads, and distorts if aspect ratio varies
<img src={product.imageUrl} alt={product.name} className="w-full" />

// ✅ Good: Reserves exact 16:9 box immediately with a subtle muted skeleton background
<div className="relative aspect-video w-full overflow-hidden rounded-xl bg-muted">
  <img
    src={product.imageUrl}
    alt={product.name}
    width={800}
    height={450}
    loading="lazy"
    decoding="async"
    className="size-full object-cover transition-transform duration-300 hover:scale-105"
  />
</div>
```

## 3. `loading="lazy"` vs. `fetchpriority="high"`

Developers often slap `loading="lazy"` on every single image in the app. **Never lazy-load above-the-fold hero images!** Lazy-loading your main banner delays Largest Contentful Paint (LCP) because the browser waits until layout finishes before even starting the image download.

### Above the Fold (Hero Banners, Navbar Logos, Top Product Image)
```tsx
<img
  src="/hero-dashboard.avif"
  alt="Platform Dashboard Preview"
  width={1280}
  height={720}
  fetchPriority="high" // Tells browser to download this immediately
  decoding="sync"
/>
```

### Below the Fold (Card Grids, Table Avatars, Footer Graphics)
```tsx
<img
  src={user.avatarUrl}
  alt={user.fullName}
  width={40}
  height={40}
  loading="lazy"     // Defers download until user scrolls near it
  decoding="async"   // Decodes bitmap off the main UI thread
  className="size-10 rounded-full object-cover"
/>
```

## 4. High-Performance Mobile Images (`expo-image` + Blurhash)

In React Native, the built-in `<Image>` component from `react-native` has weak disk caching, flickers when lists re-render, and struggles with heavy memory usage inside `<FlatList>` or `<FlashList>`.

Always use **`expo-image`** (powered by SDWebImage on iOS and Glide on Android) for mobile applications:

```tsx
import { Image } from "expo-image";
import { View } from "react-native";

// Compact 28-character Blurhash string generated by the backend when the image was uploaded
const DEFAULT_BLURHASH = "L6PZfSi_.AyE_3t7t7R**0o#DgR4";

export function CourseThumbnail({ uri }: { uri: string }) {
  return (
    <View className="w-full aspect-video rounded-2xl overflow-hidden bg-slate-800">
      <Image "100%" "100%", DEFAULT_BLURHASH blurhash: cachePolicy="memory-disk" contentFit="cover" height: placeholder="{{" source="{{" style="{{" transition="{250}" uri width: }}/>
    </View>
  );
}
```

### Why `expo-image` + Blurhash Elevates Mobile UX
1. **Zero White Flashes:** While the user is on a slow 4G connection, `placeholder={{ blurhash }}` renders a smooth, colorful blurred preview of the exact photo in `< 1ms`, then cross-fades (`transition={250}`) into the full image.
2. **Aggressive Disk & Memory Caching:** Opening the same screen twice loads images in `0ms` from native memory cache without hitting the network.

## 5. Handling Broken User-Uploaded Images Gracefully

Unlike static assets in `src/assets/`, user-uploaded URLs from S3 or external CDNs can fail or expire. Always wrap dynamic avatar and thumbnail components with an `onError` fallback state so users never see the browser's broken-image icon:

```tsx
import { useState } from "react";
import { ImageOff } from "lucide-react";

export function SafeThumbnail({ src, alt }: { src?: string | null; alt: string }) {
  const [hasError, setHasError] = useState(false);

  if (!src || hasError) {
    return (
      <div className="flex aspect-video w-full items-center justify-center rounded-lg bg-muted text-muted-foreground">
        <ImageOff className="size-6 opacity-50"/>
      </div>
    );
  }

  return (
    <img
      src={src}
      alt={alt}
      loading="lazy"
      onError={() => setHasError(true)}
      className="aspect-video w-full rounded-lg object-cover bg-muted"
    />
  );
}
```
